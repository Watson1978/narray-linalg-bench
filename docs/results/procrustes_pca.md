# D. Kabsch / Procrustes + 点群PCA

## 題材

- 点群P（1000 × 3）を、既知の回転R₀ と平行移動tで動かしたQを用意した。ノイズ無しのQ_clean、標準偏差0.01のノイズを加えたQ_noisy、R₀ に鏡映diag(1, 1, −1)を掛けたQ_reflectedの3つ。
- Kabsch: 重心を引いてH = Pᵀ Q、`svd(H)`からR = V diag(1, 1, d) Uᵀ を作る。d = sign(det(V Uᵀ))。
- PCA: X（1000 × 16、分散が2^(−j/2)で減る）の共分散を`eigh`で、中心化したXを`svd`で分解する。上位3成分が張る空間が一致することを見る。ランク10のX_lowでは、`orth`で求めた列空間と、`eigh(XᵀX)`の上位10組から作るu_i = X v_i / √λ_iの列空間が一致することを見る。

## 計測

N = 8192点、d = 256 / 512 / 1024 / 2048次元のXについて、2つの経路を別々に測った。

- `svd`: `svd(X, job: 'S')`（縦長の薄いSVD）。どの実装も`gesvd`を呼ぶ。numpyの`svd`は常に`gesdd`なので、CPUのPython版は`scipy.linalg.svd(lapack_driver='gesvd')`を通している（`python/backend.py`の`svd_gesvd`）。そろえる前の単発の値では、d = 2048のfp32でNumoがnumpyの11倍遅く見えたが、そろえた後は1.2倍だった。差はアルゴリズムの違いだった。
- `eigh`: `eigh(XᵀX)`。Rubyは`turbo: true`を付け、Numoも`syevd`を呼ぶ。Cumo、numpy、CuPyはもともと`syevd`。

## 見つけたもの

- **numo-linalg-alt 0.10.1の`svd(a, driver: 'sdd', job: 'S')`は、横長（m < n）の行列で`LapackError: the 11-th argument had illegal value`を出す**（`LAPACKE_dgesdd_work`の11番目の引数）。行列が連続でも転置ビューでも同じで、`driver: 'svd'`や`job: 'A'`なら通る。`orth`はこの組み合わせを内部で使うので、**横長の行列に`orth`を呼ぶとNumoでは落ちる。** 3 × 5でも再現した。Cumoの`orth`は横長でも通る。最初の版は行空間を`orth(Xᵀ)`で求めていたので、この関門は列空間で組み直した。
